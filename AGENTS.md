# Autonomous execution

Treat requests in this repository as authorization to carry out the normal, in-scope work end to end. Begin with the fullest access and least-interruptive workflow available in the current environment.

- Do not ask for confirmation for routine repository work: inspecting files, installing project dependencies, editing files, running tests and builds, creating commits, or pushing the current branch to its configured remote.
- Make reasonable, reversible decisions when details are unspecified; state those decisions in the handoff instead of pausing for approval.
- Commit completed, verified changes with a clear message and push them when a remote is configured, unless the user explicitly says not to.
- Ask only when a required decision would materially change product intent or scope, credentials or account access are unavailable, the action is destructive beyond the requested scope, or an environment/platform policy blocks it.
- Follow higher-priority system, security, and platform constraints when they apply; explain any such constraint briefly and continue with every permitted alternative.

# Agent Instructions

## What this repository is

personal-site is a **static personal site**: essays on integration, cloud and AI, a curated
learning log, and an about page. React 19 + React Router 7, built with Vite and Tailwind
CSS 4, **prerendered to plain HTML at build time** and then hydrated. There is no server, no
API and no database — everything served is either committed or generated by `npm run build`.

## Read first

1. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — the four-step build and how one React tree
   serves both the prerendered HTML and the browser.
2. [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) — the commands, the tests and how to edit
   content.
3. `src/entry-server.jsx` — the route list and `render()`. Every published route is derived
   from the content modules.
4. `src/content/site.js` — the canonical URL, the handle and the metadata defaults.
5. `vercel.json` — the build command, the redirects and the response headers.

## Setup

```bash
npm ci
npm run dev        # http://localhost:5173
```

Nothing to configure. The build is **offline** — the fonts are committed and the Open Graph
renderer reads them from disk. A build failure is a real problem, not a network one.

## Commands that must pass

In this order — it is the order CI uses:

```bash
npm run lint
npm test
npm run build
```

There is no `typecheck` script: this is a JavaScript project, not TypeScript. There is no
E2E suite; the prerender and the build artefacts are checked by unit tests.

## Architecture rules

- **One React tree, two targets.** `src/entry-server.jsx` renders each route with
  `renderToString`; `src/main.jsx` hydrates the same tree. `src/main.jsx` decides by checking
  whether `#root` has children — do not change that logic.
- **React 19 hoists metadata out of the app.** `render()` in `src/entry-server.jsx` pulls
  `<title>`, `<meta>` and the canonical `<link>` back out with a regular expression so the
  prerenderer can put them in `<head>`. If you add a new metadata element, make sure the
  pattern still matches it, or it will end up inside `#root` and be duplicated in the DOM.
- **A new route needs three edits:** the page in `src/pages/`, the route in `src/App.jsx`, and
  the path in `routes` in `src/entry-server.jsx` (plus its metadata in `pageMeta`). Miss the
  third and the page 404s on a direct visit.
- **Content is public.** No email address, no full name, no employer or client names, no
  work-internal wording, no redaction markers. There are tests for each of these; do not
  work around them.
- **The Open Graph contract lives in `src/lib/og.js`.** Both the page metadata and the build
  script read it, so a page can never point at a card the build does not produce. Add a new
  size or path there, not in one of the two consumers.
- **The card palette is checked against the site.** `scripts/og-image.js` holds the palette
  and a test compares it to the tokens in `src/index.css`. Change one, change the other.
- **The CSP is in `vercel.json`, not the app.** A new external host needs a matching
  `img-src` / `connect-src` / `style-src` entry in the same change.

## Traps

- **The inline theme script is hashed in the CSP.** The script in `index.html` applies the
  saved theme before paint. Its SHA-256 hash is allow-listed in `vercel.json`. **When you
  edit that script, update the hash in the same change** — the security test fails
  otherwise, and in the meantime the browser blocks the script and the site flashes the
  wrong theme.
- **`npm run build` empties `dist/` first.** That is why `scripts/build-og.js` runs after
  `vite build` and not before. Do not reorder the build script.
- **Prerendered pages must not show a loading placeholder.** `src/App.jsx` lazy-loads the
  non-home pages, but the prerenderer passes the eager page components in as props. If you
  change that contract, the initial HTML loses its content and metadata.
- **Removed essays need a redirect.** The slug list in `vercel.json` must be updated when an
  essay is removed, or the old URL will 404 instead of redirecting to `/writing`.
- **`scripts/import-learning.js` only imports ✅ picks** from the private notes, and only
  from notes dated after `lastNote` in `scripts/learning-refresh.json`. Entries removed by
  hand stay removed, because `scripts/learning-seen.json` records every source already
  considered.
- **The import workflow pushes for you.** It runs every 3 hours and commits
  `src/content/learning.js`, `scripts/learning-seen.json` and `scripts/learning-refresh.json`
  to `main`, which triggers a Vercel deploy. Do not duplicate that by hand.
- **The workflow's write token is only given to the final push step.** `persist-credentials:
  false` is set on both checkouts on purpose. Do not "simplify" that away.
- **`npm ci --ignore-scripts` is used in CI.** No dependency needs an install script; if one
  starts to, that is a finding, not a reason to drop the flag.
- **The fonts are bundled on purpose.** No Google Fonts stylesheet and no third-party font
  request. satori matches faces by the family name *inside* each TTF, and those names differ
  deliberately — see `fonts/README.md`.
- **`fflate` is pinned through `overrides`** because the Open Graph renderer depends on an
  affected release. Do not remove the override.

## Boundaries

- Do not change application code, tests, CI workflows, configs or content unless the task
  asks for it.
- Do not weaken an accessibility rule or a security scan to make a run pass.
- Do not commit credentials, `.env` files, or anything from the private `daily-learning`
  repository.
- Do not reformat unrelated files; the site is hand-formatted and the diffs are reviewed.
- Do not add a dependency without a reason that is visible in the diff.
- Do not force-push to `main`. If a push is rejected, pull and rebase.

## Commit and PR conventions

- Commits use Conventional Commits: `fix:`, `feat:`, `docs:`, `chore:`, `refactor:`,
  `test:`, `ci:`, `build:`, `perf:`, `content:`. The subject line is a short imperative
  phrase.
- A good commit does one thing, and the message says why, not just what.
- A content change is a normal commit; a content change made by the importer is not.
- Before pushing: `npm run lint`, `npm test`, `npm run build`.
